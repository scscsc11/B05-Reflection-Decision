# B05 提交清单（交队长核对）

依据赛题任务详情、选手提交模板和仓库当前实现整理。最终以比赛平台当次栏目和队长确认为准；不要把官方自测原件、密钥或本地日志放进公开仓库或提交包。

## 代码包

- [ ] 使用 `<队伍名称>_代码_<版本号>.zip` 命名；压缩包根目录有 `Dockerfile`、`run.sh`、`requirements.txt` 和 `src/`，不上传 Docker 镜像。
- [ ] `run.sh` 保持评测调用方式 `bash run.sh --task <值> --test --out-dir /output`；容器读取只读 `/input`，结果写 `/output`。
- [ ] 正式处理器完成后，在 `norethink/` 与 `rethink/` 下为每个输入生成同名 JSON，内容为 `{"results":[...]}`，数组长度与输入装备数量一致。
- [ ] 大模型地址、密钥和模型名从授权环境注入；代码包不含 `.env`、真实令牌、自测数据或开发日志。
- [ ] 用 `dev/tests/check_submission.py --code <代码包>` 检查包结构，并对候选提交做真实容器运行。夹具通过不等于正式算法通过。

## 方案包与文档

- [ ] 使用 `<队伍名称>_方案.zip`；内有 `<队伍名称>_方案/`，其下的 `<队伍名称>_Scene/` 放配套场景 JSON。
- [ ] 方案包内有红蓝对抗场景描述 PDF、反思式决策解决方案 PDF、答辩汇报片 PPTX；场景数据与描述报告一致。
- [ ] 初赛技术报告为 V1.0，不超过 50 页；成果简介不超过 1500 字。
- [ ] 用 `dev/tests/check_submission.py --materials <方案包> --intro <成果简介>` 做离线检查；该脚本只检查部分结构，仍需人工核对报告内容、文件名和平台栏目。

## 平台与时间（待队长确认）

- [ ] 核对平台是否将代码包、方案包、成果简介设为独立上传栏目；赛题 PDF 的“方案包包含答辩汇报片”和“初赛成果简介”需逐项映射到平台。
- [ ] 核对队名、版本号、最终截止时间及每次提交机会。赛题 PDF 写有线上比测每队最多 15 次、每天最多 1 次，周二 17:00 前提交的结果周五更新；以平台实际规则为准。
- [ ] 最终上传、对外提交由队长确认；保留候选提交号、冒烟记录目录、结构检查结果和正式处理器验收结论。

# B05 场景数据与材料验收要求

## 材料交接

研究生 A 确认场景内容、数据版本和技术结论。本科生二将已确认的团队场景材料整理到 `data/team_scenario/`，逐项记录文件名、用途、报告章节、版本日期和确认状态。报告中的案例编号、输入条件和数值取自清单对应的数据文件。发现两者不一致时，记录文件位置、章节和差异，交由研究生 A 核对。

每个数据版本保存输入文件、材料清单和对应报告。清单记录相对路径、文件 SHA-256 摘要和数据来源。改动案例内容、参考标签或划分时另建版本，记录受影响的案例编号，并保留原数据和运行结果。

## 软件输入与输出检查

1. 按清单核对文件和报告引用。输入 JSON 使用 UTF-8 编码，键名唯一。检查必需字段、字段类型和数据尺寸。
2. 通用场景格式校验由 `scene_io.load_scenes` 执行。检查输入目录顶层 JSON、文件名声明的维度，以及矩阵和向量中的有限数值。使用固定值夹具时，验收记录覆盖 `norethink/` 和 `rethink/` 两个目录同名结果的存在性、字段类型和列表长度。见 [场景读写与结构校验](../../dev/src/scene_io.py)。
3. 候选提交包可用 `dev/tests/check_submission.py` 核对归档结构、文件存在性和结果目录。检查记录写明实际提供的包和目录，并保留检查输出。见 [提交包结构检查](../../dev/tests/check_submission.py)。

## 民用校园工单示例

民用工单包验证反思、经验查询和离线评分流程。冻结版本含 8 条种子工单和 24 条留出工单。留出集中账户、课程资料、排课和其他问题各 6 条。见 [冻结数据清单](../experiments/support_tickets_v1/manifest.json)。

| **路径** | **内容与验收要求** |
| --- | --- |
| `seed_input/benchmark.json` | 用于构建知识种子。检查领域、类别定义和案例字段。 |
| `seed_input/answers.json` | 种子案例编号到类别的映射，覆盖种子输入中的全部编号。 |
| `heldout_input/benchmark.json` | 留出推理输入。该目录仅放此文件，与种子集的案例编号无交集。 |
| `offline/answers.json` | 留出案例编号到类别的映射，覆盖全部留出案例。离线评分器读取时按清单摘要核验，并解析同一份数据。 |
| `offline/label_rationales.json` | 按案例编号查找标签依据，供资料复核。 |

两个 `benchmark.json` 均包含 `domain`、`labels` 和 `cases`，且领域与类别定义一致。每例含非空的 `id`、`topic` 和 `text`，可附字符串数组 `features` 描述已观察到的条件。验收时核对集内编号唯一、跨集编号不重合、参考标签取自类别表，并检查跨集文本重复。见 [工单数据加载器](../../dev/src/reflection.py)。

## 报告与证据

- **数据与划分。** 说明案例来源、标签依据和划分口径，引用相应版本的清单。民用示例由模型编制，逐例以工单的主要诉求为标签依据。
- **复现条件。** 记录代码提交、数据版本和运行环境。对照实验记录模型来源、复核轮数和每阶段的模型调用时间预算。三组复核共用一次冻结初判，有历史组和条件复核组读取同一份种子库。
- **结果与来源。** 结构验收记录输入输出路径和检查结果。效果比较引用对应的离线评分文件，记录改对、改错和持平的案例数。调用成本注明记录来源，运行中断时同时保留各次调用日志。每项结论对应实际测试环境，进程内替身与脚本化网关产生的结果用于流程验收。真实模型表现和正式评测采用各自的实跑结果。

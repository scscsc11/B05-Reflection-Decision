## 3. 具体任务

### A. 开发运行支撑模块 `processor_runtime.py`
这是你负责的实际代码模块。根据双方协商确定的调用接口，提供通用工程能力，例如：
- 运行时间记录和阶段计时；
- 时间预算状态的读取与记录；
- 结构化运行日志；
- 通用配置项的读取、类型检查和默认值管理；
- 统一的运行状态与异常信息封装。

开始编码前，共同确认最小函数接口，并把接口写入 `PROCESSOR_SUPPORT_REPORT.md`。接口确认后再实现，避免两边代码对不上。

### B. 开发接口契约测试
创建 `test_processor_contract.py`，检查：
- processor 模块是否可导入；
- `process(scene, mode)` 是否存在；
- 输入参数是否按约定传入；
- 返回类型和结构是否满足研究生A的接口契约；
- 非法输入是否有明确错误表现；
- 处理器是否错误地自行写输出文件。

### C. 开发运行支撑模块测试
创建 `test_processor_runtime.py`，覆盖：
- 计时和耗时记录；
- 时间预算状态记录；
- 配置缺失、类型错误和默认值；
- 日志字段完整性；
- 异常状态记录。

### D. 测试夹具与回归
在 `processor_test_fixtures.py` 中整理可复用测试输入。测试字段必须来自实际接口定义，不猜字段、不修改官方原始数据。

处理器模块更新后，运行接口回归并报告：
- 测试对应的 Git 提交号；
- 测试命令；
- 通过和失败用例；
- 失败时的最小复现说明。

接口测试通过只说明软件契约符合，不代表核心算法性能已经得到验证。

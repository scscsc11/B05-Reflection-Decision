## 2. 处理器方向的协作边界

### 王浩然负责
- 处理器核心算法研究、设计和实现；
- `dev/src/processor.py`；
- `dev/src/processor_helpers.py`（核心算法确有必要时）；
- 算法模块自己的单元测试；
- 与邓咏慷共同确认辅助模块的接口和调用方式。

### 邓咏慷负责
- `dev/src/processor_runtime.py`：通用运行支撑模块，例如运行计时、时间预算状态记录、结构化日志、配置读取与格式检查；
- `dev/tests/test_processor_contract.py`：处理器接口契约测试；
- `dev/tests/test_processor_runtime.py`：运行支撑模块测试；
- `dev/tests/processor_test_fixtures.py`：独立测试夹具；
- `docs/processor/PROCESSOR_SUPPORT_REPORT.md`：辅助模块和测试报告；
- 与王浩然协商确定接口，完成分配给自己的辅助代码和软件联调。

邓咏慷的模块不实现核心领域求解逻辑，不自行改变算法目标、约束或决策规则。王浩然对核心算法及最终算法结果负责。

## 6. 接口与模块依赖

### 正式处理器接口
```python
process(scene, mode) -> list[int]
```
最终字段、模式取值、列表长度和合法范围以当前 `main.py`、`scene_io.py` 和官方说明核实，不得猜测。

- 舒超：接口契约、主程序装载和统一输出。
- 王浩然：处理器核心实现。
- 邓咏慷：通用运行支撑、独立接口测试和回归。
- 处理器不自行读取输入目录或写结果文件；统一 IO 层负责校验和输出。

### 通用 Agent 与知识流程
```text
main.py / 实验入口
  └── reflection.py（舒超）
        ├── llm_client.py（王浩然）
        └── experience_store.py（舒超）
  └── score_benchmark.py（舒超）
```

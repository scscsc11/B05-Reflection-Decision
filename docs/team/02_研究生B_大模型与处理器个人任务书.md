**角色：真实大模型接入、处理器核心算法设计与实现**  
**分支：`task/gradB-llm-processor`**

## 1. 工作定位

你集中负责两项核心工作：
1. 真实大模型服务接入；
2. 正式处理器核心算法研究、设计和实现。

邓咏慷承担处理器方向中范围明确的辅助运行模块、接口测试和回归工作；你负责核心算法和核心实现。双方按各自任务分工协作，共同确认接口并完成联调。

## 3. 具体任务

### A. 真实大模型接入
在现有 `llm_client.py` 基础上推进：
- 从 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 读取配置；
- 完成获授权真实模型服务的最小请求；
- 处理认证失败、限流、超时、HTTP 错误和无效结构化响应；
- 明确超时、重试和调用预算；
- 返回稳定、可供研究生A的 `reflection.py` 调用的结构；
- 日志脱敏，绝不输出 API Key。

没有真实网关授权或凭据时，如实标记真实联调未开展，不得伪造调用记录。

### B. 处理器核心模块
负责 `processor.py` 和必要的 `processor_helpers.py`：
- 先核对研究生A维护的正式接口契约；
- 负责处理器核心算法的研究、设计和实现；
- 保持统一入口 `process(scene, mode) -> list[int]`；
- 不自行读取输入目录、不自行写结果文件；
- 不修改 `main.py` 和 `scene_io.py`；
- 与本科生一共同确定运行支撑模块的接口；
- 提供模块说明、测试方法和当前实现状态。

### C. 与邓咏慷协作
邓咏慷负责分配给他的辅助代码和独立测试；你负责核心算法和核心实现。双方需要：
- 共同确认 `processor_runtime.py` 的函数接口和调用约定；
- 明确接口测试需要覆盖的输入输出要求；
- 分别维护自己负责的文件；
- 在模块完成后共同进行接口联调，发现问题后由对应文件负责人修改。

邓咏慷承担范围明确的辅助开发任务，不承担核心算法的整体设计和最终实现责任。

### D. 模块级测试
维护：
- `test_real_llm_smoke.py`：真实模型最小请求；
- `test_processor_algorithm.py`：处理器模块自身的单元和边界测试。

### E. 文档
创建：
- `docs/agent/REAL_MODEL_INTEGRATION.md`
- `docs/processor/PROCESSOR_IMPLEMENTATION.md`

记录配置方式、接口、错误处理、模块状态、测试命令和已知限制。

## 4. 输入与输出

输入：官方接口要求、舒超接口契约、获授权模型网关信息、现有源码、邓咏慷提供的运行支撑模块。

输出：
- `llm_client.py`；
- `processor.py` 和必要辅助文件；
- 两类模块测试；
- LLM 和 processor 实现说明；
- 真实模型运行记录或未能联调的明确原因；
- 给舒超的集成说明；
- 与邓咏慷确认的辅助模块接口说明和联调记录。
